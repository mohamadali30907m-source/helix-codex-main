# My Journey

If someone had told me a year ago that I would build something like Helix Codex, I probably wouldn't have believed them.

This project didn't start with a detailed plan.

It started with curiosity.

One day I was scrolling through social media when I found Hack Club. I spent hours reading about it. I liked the idea that teenagers from different countries were building real things together instead of just watching tutorials.

That made me want to build something of my own.

At first, I wasn't thinking about robotics or biomedical engineering.

I was only thinking about building something that looked good.

Then the idea slowly changed.

Every day I learned something new.

A new technology.

A better way to organize files.

A cleaner design.

A different way to solve a problem.

Without noticing, the project became much bigger than I expected.

The biggest mistake I made was trying to make everything perfect before showing anyone.

I kept redesigning pages.

I kept changing colors.

I rebuilt components more than once because I always believed there was a better version waiting.

I thought that once everything became perfect, I would publish it.

That day never came.

After spending more than thirty-five hours working on the project, I finally sat down and carefully read the Hack Club Shipping Guide.

That moment was honestly difficult.

I realized that almost all my work existed only on my computer.

I hadn't been documenting my progress.

I wasn't committing regularly.

I wasn't thinking about shipping.

For a while, I felt like I had wasted a lot of effort.

Then I understood something important.

The project wasn't the problem.

My workflow was.

That realization completely changed how I think about programming.

Now I understand that writing code is only one part of software development.

Planning matters.

Documentation matters.

Version control matters.

Shipping matters.

Perfection doesn't.

Helix Codex became more than just another project.

It became the place where I learned how to build larger applications without getting lost.

It taught me how to break problems into smaller pieces.

It taught me that deleting code isn't failure.

Sometimes rewriting something is exactly what helps you understand it better.

There are still many unfinished ideas inside this repository.

Some pages still need work.

The backend is still growing.

Hardware integration is still coming.

But that's okay.

This repository isn't supposed to represent perfection.

It represents progress.

If someone opens this repository a year from now, I hope they notice one thing.

Not that the first version was amazing.

I hope they notice how much it changed.

Because if Helix Codex keeps improving, it means I kept learning.

And that's the real goal.

I'm still a student.

I'm still learning.

I'm still making mistakes.

But now I'm no longer waiting until everything becomes perfect before sharing my work.

I build.

I learn.

I improve.

Then I build again.
